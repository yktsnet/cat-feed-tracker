# Guarantee Ledger

このリポが外へ約束している振る舞いと、それを守るテストの一覧である。約束が破れればテストが落ちるので、
ここに書いたことは気づかないうちに実装とずれていかない。**ここに載っていない振る舞いは約束ではなく、予告なく変わりうる。**
対象はサーバの HTTP API（`GET /healthz`・`POST /api/events`・`POST /api/webhook/line`）と、LINE に届く通知の本文である。通知の本文はテストが関数を直接呼んでいても、そのまま利用者に届くので載せる。DB スキーマ・SQL・Pico W 側の実装は対象外とする。

- 目的: いま何を約束しているかを1か所で読む。変更の前に、破ってはいけない約束をここから探す。テストの無い約束を Gaps に残す
- 分け方: 約束の対象（エンドポイント・通知）ごとに1ファイル。テストファイルや Issue の単位では分けない。新しい対象を作ったときだけファイルを足す
- 書き方: 各ファイルに「保証｜対応テスト」の表を1つ置き、1行に約束を1つ、宣言文で書く。出典・経緯・設計の理由は書かない。LINE の画面での見え方、手で確かめる操作、構文チェックは載せない。約束が10行以上のファイルは、何についての約束かで `##` の見出しを立て、見出しごとに表を置く。1つの見出しには3行以上を入れ、3行に満たないまとまりは近い見出しにまとめる。見出しは行の主語になる名詞句にする。10行未満のファイルは見出しを置かない。約束が増えてもファイルは分けない。行を足して10行以上になったときは、その変更の中で見出しを立てる
- 引き方: Issue で「維持する保証」を挙げるときは、変更の対象のファイルを開いて約束を引く。テストが落ちたら、テストの名前で台帳を検索すると、破れた約束の行が見つかる。約束が守られていることは、全テストを流す CI が確かめる。コードのファイルから約束を引く仕組みは置かない（実装とテストの名前は1対1でなく、機械では正確に引けない）
- 運用: 変更の前にこの README を読み、変更が触れるファイルから「維持する保証」を引く。約束を足す・変える・消すときは、承認を受けた保証節の文のまま、該当するファイルの表に行を足す・直す・消し、対応テストも同じ変更で直す。Issue や作業ごとにファイルや節を起こさない。テストの無い約束は Gaps に書き、テストを足したら表へ移す。乖離は `guarantee-audit` で棚卸しする
